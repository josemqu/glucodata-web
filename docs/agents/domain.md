# Domain Docs

This repo uses a single context: `GLOSSARY.md` at the repo root and `docs/adr/` for architecture decisions.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being changed. If these documents do not exist, proceed silently. Domain documentation is created when terms or decisions are resolved through `/domain-modeling`.

## Vocabulary

Use the glossary terms in specifications, issues, proposals, and tests. If a needed concept is absent, check existing project terminology before proposing a new term.

## Architecture decisions

Flag conflicts with an existing ADR explicitly, identify the decision, and explain why it should be reconsidered.
